# Go-To-Market Focus

## Starting Segment

The first real customer segment is culinary/pastry schools.

This is not because the long-term product is limited to schools, but because
the current request came from a school context and the workflow is concrete:

- Students need calculators during lessons.
- Teachers need consistent recipe logic and ranges.
- Recipes can become assignments and technical cards.
- Telegram/PWA launch makes sense for classroom use.
- Schools can validate whether the tool is useful before broader expansion.

## MVP Customer

Primary MVP customer:

- Pastry or culinary school owner/admin.
- Teachers who need students to calculate and understand recipes.
- Students who need a mobile-first tool from Telegram or PWA.

## MVP Product Promise

Help schools teach recipe formulation by giving students a mobile calculator
that:

- Builds a recipe from known ingredients.
- Shows technical balance.
- Explains out-of-range values.
- Can later save, submit, export, and compare recipes.

## Scope Guardrail

Long-term ideas are valuable, but MVP should not chase all of them at once.

Prioritize:

1. Ice cream calculator quality.
2. Mobile/Telegram/PWA classroom flow.
3. Accounts, school membership, and saved recipes.
4. Technical card/export basics.
5. Teacher/student workflows.

Defer:

- Public RecipeHub.
- Paid creator accounts.
- Public API for AI services.
- Multi-domain culinary calculators beyond the first proof.

## Expansion Path

After school MVP works:

1. Add more calculators for the same schools.
2. Add exports, recipe books, and assignments.
3. Add broader culinary modules.
4. Add creator/RecipeHub features.
5. Add public/API/AI-facing capabilities.
